# 04 — Visual Audit & UI Polish

## Audit order

1. User flow
2. Information architecture
3. Missing/misplaced information
4. Interaction design
5. Hierarchy
6. Layout/alignment
7. Typography
8. Color
9. Micro-polish

Do not perfect shadows while the main action is structurally wrong.

## Hierarchy

There should usually be one dominant focal point, followed by clear secondary and tertiary levels.

If everything is bold, saturated, large, or boxed, hierarchy disappears.

## Alignment grid

Define consistent page margins and shared edges. Text, cards, icons, controls, and sections should align deliberately.

Then apply optical correction where geometry alone looks visually off.

## Color

Use color intentionally. Define roles such as:
- accent;
- success;
- warning;
- destructive;
- neutral;
- muted;
- surface;
- border.

Avoid many saturated colors competing for attention.

## Typography

One strong font family is usually enough. Build hierarchy with size, weight, color, line height, and spacing.

Body text should be comfortable, not dense or overly high-contrast. Small uppercase labels may benefit from modest tracking.

## Badges and labels

Badges must scan instantly. Keep them concise and avoid combining long text, icons, heavy backgrounds, borders, and excessive padding in tiny components.

## Icon consistency

Icons in one interface should share a visual language: stroke weight, corner treatment, fill logic, optical size, and color strategy.

Avoid mixing unrelated sets casually.

## Dividers

Dividers should organize, not become focal points. Prefer separation by:
1. spacing;
2. grouping;
3. subtle surface differences;
4. divider lines as a last step.

## Spacing communicates relationships

Related items should be closer. Section boundaries should have larger gaps. Equal gaps everywhere weaken semantic grouping.

## Primary CTA

A primary action should be obvious without shouting. Prefer hierarchy through position, contrast, sizing, spacing, and clear wording rather than ALL CAPS, giant type, extreme saturation, or oversized shadows.

## System robustness

A design must work across real content variations and image backgrounds. If an overlay icon is readable only on one lucky image, the system is fragile.

## Ask why

Every major design change should improve at least one of:
- hierarchy;
- readability;
- cognitive load;
- accessibility;
- grouping;
- interaction effort;
- context;
- uncertainty;
- variable-content robustness.

If you cannot explain what improved, reconsider the change.
