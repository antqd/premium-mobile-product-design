# 07 — Final Checklists

## New screen checklist

### Purpose
- Can the screen's job be described in one sentence?
- Is there one dominant task?

### Hierarchy
- Is the most important information immediately obvious?
- Is the primary action clear without shouting?

### Navigation
- Are there too many destinations?
- Should global navigation disappear in this context?

### Density
- Is this desktop-level information density?
- Can anything move to another screen or sheet?

### Typography
- Is any text unnecessarily small?
- Is the hierarchy coherent?

### Spacing
- Do related elements group naturally?
- Did nested containers create excessive padding?

### Touch
- Are hit areas comfortable?
- Are frequent controls reachable?

### States
- Empty?
- Loading/processing?
- Error?
- Keyboard-open?
- Long content?

### Motion
- Does transition direction preserve orientation?
- Does tapping/selecting give feedback?
- Is reduced motion supported?

### Robustness
- Long titles?
- Large numbers?
- Missing images/data?
- Real production content?

## Audit checklist

1. Fix flow before polish.
2. Verify information appears where the user needs it.
3. Check one dominant focal point.
4. Snap major elements to a shared grid.
5. Simplify typography.
6. Reduce competing color.
7. Normalize iconography.
8. Use spacing to express relationships.
9. Keep dividers quiet.
10. Put sequential controls together.
11. Reduce uncertainty before important actions.
12. Verify sticky context/action only when useful.
13. Test real content variations.
14. Interact with the screen, not only inspect a screenshot.

## Desktop → mobile conversion

1. Inventory navigation, actions, modules, filters, forms, analytics.
2. Rank each item as critical / frequent / contextual / secondary / rare.
3. Choose mobile navigation.
4. Define one primary job per screen.
5. Rebuild layout instead of compressing it.
6. Move secondary actions into sheets, overflow, long press, or deeper screens.
7. Verify empty, populated, keyboard, loading, error, small-device, and long-content states.

## Final product-quality principle

A successful mobile interface should feel:
- simple without feeling empty;
- spacious without wasting space;
- fast to understand;
- comfortable to touch;
- contextual;
- visually hierarchical;
- predictable;
- native to mobile;
- responsive and alive;
- recognizable without becoming unfamiliar.
